# Releases

A **release** is a bundle of content changes that goes live as one. Think of a product launch where the landing page, the navigation entry, and the announcement post must appear at the same second. Publishing them one by one means visitors briefly see a navigation entry pointing at a page that doesn't exist yet.

With a release you prepare everything quietly in the background, review it as a set, and then publish it in a single moment, or schedule that moment for the middle of the night. The background is in [Releases](../concepts/releases.md).

## Creating a release

Click *New Release* and give it a name, for example "Spring campaign", plus a description if it helps your colleagues. The release starts as a **draft**.

## Putting content into a release

You do not add pages from the release screen. You add them while editing.

When you have finished a page that belongs to the launch, save or publish it **into the release** instead of publishing it directly. Your work is attached to the release, and the live website stays exactly as it was. The release's own page then lists everything it contains, which doubles as the review checklist before you go live.

## The three states

| State | What it means |
| --- | --- |
| **Draft** | Open for changes. Content can be added and removed. |
| **Scheduled** | It has a date and time and will publish itself automatically. |
| **Published** | Everything in it went live together. |

The overview groups scheduled and unscheduled releases and shows how many items each one holds.

## Publishing

::: tip Highlight
Everything in a release goes live in the same instant, not one page after another. Visitors never catch the site half-updated, with a new navigation entry pointing at a page that has not appeared yet.
:::

Publish a release straight away, or set its schedule and let it publish itself. Either way, everything in the release becomes live at the same instant, so visitors and caches switch from the complete old state to the complete new state with nothing in between.

Deleting a release does **not** delete the content in it. The versions stay in each page's own history, exactly where you left them.
